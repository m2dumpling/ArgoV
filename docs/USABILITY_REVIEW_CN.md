# ArgoV 易用性与可编辑性审视

审视日期：2026-10-11。基于 `85864b3` 及本次本地修改，覆盖安装、协议管理、凭据、用户与配额、订阅、端口跳跃、中继、WARP、服务、升级和卸载。

审视方法：检查菜单到配置、证书、分享链接和订阅的完整路径；在隔离临时目录运行测试，并使用 Xray 26.3.27、Sing-box 1.14.3 校验生成配置。本地审视未操作公网 VPS；后续用户反馈其 VPS 测试的所有节点均可正常使用，并授权发布。该反馈不代表全部历史部署或系统环境均已实机验证。

## 结论

HY2 原流程存在“域名直接沿用 Bing”“算法菜单与实际配置不一致”“客户端未收到对应参数”的问题。本次已贯通首次配置、安装后编辑、证书、内核配置和订阅。Sing-box 原先主要提供添加、删除，现已为五种协议补齐编辑入口。

首次安装的 Sing-box 步骤现只询问是否安装内核；协议作为安装后增配项，从 `s → s2` 添加。没有节点配置时不启动或启用 Sing-box 服务；已有配置不在首次向导中重建。

其他模块仍有已确认的改进项。新增 HY2/Sing-box 编辑的恢复保障，不等于所有安装、删除和升级流程都已经具备相同保障。

## HY2 新流程

首次搭建：选择 HY2 → 接受或修改域名 → 选择 UDP 端口 → 选择算法 → Brutal 时填写带宽 → 设置或关闭跳跃 → 查看摘要 → 确认全部安装设置。

| 配置 | Xray | Sing-box |
| --- | --- | --- |
| 首次域名 | 默认 `www.tesla.com`，可回车接受或修改 | 必填，不沿用其他协议的默认域名 |
| 编辑域名 | 回车保留当前配置 | 回车保留 HY2 独立配置 |
| 拥塞控制 | BBR、Brutal、Reno、自动协商 | BBR、Brutal、客户端协商 |
| Brutal 配置 | `brutalUp` / `brutalDown`，带单位 | `up_mbps` / `down_mbps` |
| BBR | `congestion=bbr` | 清除带宽参数，`ignore_client_bandwidth=true` |
| BBR 预设 | 不展示 Sing-box 特有配置 | 支持 1.14+ 的 standard / conservative / aggressive |
| 跳跃 | 新节点默认启用，优先 `47000-48000`；可输入其他范围或 `off` | 新节点默认启用，优先 `49000-50000`；可输入其他范围或 `off` |
| 编辑入口 | `ag → a → e4` | `ag → s → s2 → e1` |

域名是 TLS/SNI 和证书身份，不是落地中继、代理出口或网站反向代理地址。向导使用自签证书，不要求域名所有权或 DNS 指向 VPS；HTTPS 订阅域名的要求则不同。编辑时按字段提示用 `0` 或 `cancel` 返回。

带宽提示区分方向。例如服务器上传 80 Mbps、下载 120 Mbps，对应客户端上传 120 Mbps、下载 80 Mbps。内置 Mihomo 转换会生成对应 `up` / `down` 和证书 `fingerprint`；其他通用 URI 客户端可能忽略带宽提示，需要自行设置。Sing-box 的 Brutal 需要客户端参与带宽协商，服务端选项不能替客户端选择算法。

Brutal 没有已有带宽值时默认服务器上传 100、下载 200 Mbps；已有有效数值继续保留。新节点的默认跳跃范围避开另一组跳跃、已配置端口和实际 UDP 监听；已部署节点原先关闭跳跃时，回车编辑仍保持关闭。

修改域名后会检查证书是否匹配，必要时生成包含 SAN 的新证书并更新指纹；域名、证书和私钥仍匹配时复用原证书，避免无意义地更换指纹。更新连接参数、证书或 SS2022 密钥后，客户端须刷新订阅。

## 本次已修复

| 方面 | 原问题 | 本次结果 |
| --- | --- | --- |
| HY2 首次输入 | 默认 Bing，无专门的域名和算法配置流程 | 双核域名可编辑；Xray 首次默认 Tesla，Sing-box 自行输入；新增算法、带宽、跳跃摘要 |
| 选项真实生效 | Xray Brutal 使用无效的 `up/down` 字段；算法说明有误 | 改为支持的字段；提供 BBR、Brutal、Reno、协商选项 |
| Sing-box HY2 | Reno、BBR 预设及跳跃间隔等存在无效或版本不兼容选项 | 删除不支持的 Reno；按版本提供 BBR 预设；说明间隔由客户端控制 |
| 输入校验 | 错误域名、端口、带宽、编号可能直接写入 | 共用输入函数，错误重试、取消返回、EOF 取消；规范化域名和端口 |
| 端口冲突 | 忽略正在配置的其他协议、跳跃范围和 IPv6 监听 | 检查已选端口和范围重叠；识别 IPv6 TCP/UDP 监听；编辑允许保留现有端口 |
| Sing-box 跳跃 | 协议启用后可能缺少有效规则和开机恢复 | HY2 增配/编辑时应用并检查规则；失败关闭跳跃并提示监听端口连接；提供 systemd / OpenRC 恢复服务，重复执行不叠加规则，关闭仅删除项目所属规则 |
| 端口耗尽 | 65535 已占用时仍可能返回该端口 | 无可用端口时返回失败 |
| 协议隔离 | Sing-box 共用 SNI 和 SS 加密设置 | HY2、TUIC、AnyTLS、Reality 独立 SNI；Sing-box SS 独立加密方法 |
| 证书隔离 | HY2 与 TUIC 共用证书，改域名可能影响 TUIC | 新 HY2 使用独立证书；存量节点兼容迁移 |
| 可编辑性 | Sing-box 改配置需删除重建 | 五种协议可直接编辑，保留现有密码和端口，支持按需换新密码 |
| 配置一致性 | 部分 Xray 设置只改保存变量，未修改实际入站 | Reality SNI 和 SS 加密快捷入口转到实际入站编辑 |
| 编辑失败 | 写入后才发现无效，服务失败可能仍显示成功 | HY2/Sing-box 编辑使用快照、候选配置和内核检查；失败恢复配置、用户、证书；旧服务启动失败会明确提示 |
| 中继保留 | 协议重建需要保留已有 Sing-box 中继 | 保留中继；备份、解析或合并失败保留旧配置，阻止静默变为直连 |
| 分享与订阅 | Sing-box `hy2://` 被 Mihomo 转换漏掉 | 同时识别两个 HY2 URI 前缀，保留域名、跳跃、指纹、Brutal 带宽 |
| 字符处理 | 密码中的引号、反斜杠、`@`、`&` 易破坏 JSON 或 URI | JSON 值安全编码；Sing-box 密码 URL 编码；订阅节点名编码；订阅 VMess JSON 使用 jq 构造 |
| 旧配置 | 新字段可能失去旧 SNI、证书、方法 | 继承旧有效配置，保存白名单和读写往返覆盖新字段 |
| SS2022 用户 | 独立用户使用普通随机十六进制字符串 | 按方法生成 16/32 字节 Base64 密钥；保留有效密钥，修复不匹配密钥 |
| Xray 用户同步 | HY2 入站在前时会改写共享用户集合，后续 VLESS/Reality 同步失败 | HY2 使用独立的入站用户变量，验证不同入站顺序和多用户 |
| 证书指纹 | HY2 回填可能读取 TUIC 证书；TUIC 导出不带固定信息 | 读取实际入站证书，覆盖普通分享、默认及独立用户订阅；只回填指纹，不换证书 |
| 新订阅参数 | VLESS Encryption 被覆盖、XHTTP 等传输被丢掉；TUIC 拥塞字段名错误 | 保留支持的参数，复杂不支持参数明确说明；Mihomo 使用 `congestion-controller` |
| WS 路径导出 | 编辑后的路径没有同步到分享和订阅 | 读取实际配置路径，保留旧默认路径和早期数据参数 |
| 订阅脚本生成 | 名称或 Token 的引号、反斜杠、换行可能破坏 Python | JSON 编码传值，语法预检后替换；原 Token、路径和名称保留 |
| 内核更新 | 下载后直接覆盖内核；失败仍可能报告成功 | 使用候选内核校验现有配置，失败不替换；启动失败回滚，停止的服务保持停止 |
| Sing-box 检测与错误提示 | 只查 PATH；缺配置预检拒绝误报为下载失败；删除文件后旧进程仍被显示为“运行中、未安装” | 识别实际进程及常见安装路径；区分残留运行状态；按实际配置路径预检；保留准确的阶段错误 |
| Sing-box 卸载 | 停止失败仍可能继续删除内核、配置和证书 | 停止后检查服务状态与 PID；仍运行则取消卸载 |
| Sing-box 最新版本 | 按行匹配 `tag_name`，单行 JSON 会漏掉版本；API 错误被隐藏 | 使用 JSON 解析，校验版本字段并显示请求或响应错误；固定版本继续保留，失败不修改旧节点 |
| Sing-box 面板状态 | 未安装时状态、版本重复显示“未安装”，`s1` 固定走更新模式 | 独立标示版本，按已安装或运行状态选择安装/更新；残留进程保护继续生效 |
| 错误可见性 | 配置锁的 `exec` 重定向会持续屏蔽主脚本 stderr | 重定向仅作用于文件描述符开关操作，后续错误仍可显示 |
| TLS 中继 | 导入仍生成新 Xray 已删除的 `allowInsecure=true` | 有指纹则使用证书固定；缺指纹或双核不支持时拒绝本次操作，保留原配置与服务 |
| 取消安装 | 选协议时提前保存；无节点也可能继续 | 收齐配置后统一确认再保存；检测未选节点和被关闭的 Sing-box |
| 重装影响 | 安装过程强杀、停止并禁用系统 Nginx | 移除对 Nginx 的清理，仅停止本项目对应服务 |

## 待改进

P1 表示应优先修复的可靠性或配置一致性问题；P2 表示体验、维护或诊断问题。以下是代码审视结果，不代表已在实际 VPS 上复现全部故障场景。

| 优先级 | 模块和代码位置 | 已确认的行为及影响 | 建议 |
| --- | --- | --- | --- |
| P1 | 首次安装：`interactive_install`、`build_xray_config` | Argo 起始端口只校验单个端口，随后直接 `+1/+2`，可导致越界；跳过隧道仍生成内部入站；CDN 端口、UUID、固定隧道输入未统一校验 | 全部字段接入校验，三端口同时检查范围和占用；按启用状态生成入站和管理菜单 |
| P1 | 订阅 HTTPS：`interactive_install`、`edit_subscription` | 2096 占用后顺序找空端口，可能得到 CF 不支持代理的端口；编辑端口未检查占用；保存后直接报成功 | 明确 CF 代理/直连模式；CF 模式仅在支持集合中选择；启动和请求检测后报告结果 |
| P1 | 完整安装与服务：`do_install`、`sb_start`、`sb_restart`、`start_sub_server` | 部分依赖、内核及服务操作未传播失败；主流程仍可能输出成功；缺少完整安装回滚 | 各步骤返回明确状态，检查进程和监听；提供分项失败、重试和恢复 |
| P1 | Xray WS 路径编辑：`edit_protocol` | 分享与订阅已同步实际路径；旧编辑流程仍缺少统一的输入校验和事务，重复改路径时 fallback 仍需完善 | 将旧编辑流程接入候选配置与回滚，按实际旧路径同步 fallback |
| P1 | Xray Reality/SS 旧编辑与添加：`edit_protocol`、`add_single_protocol` | 部分输入直接参与算术或 JSON；改密码/加密方式缺少统一校验；没有 HY2 编辑的完整恢复 | 迁移到共用表单、候选文件和恢复流程；明确凭据变化的用户影响 |
| P1 | Sing-box 用户端口：`sb_sync_users` | 基准端口 `+10+序号`，未排除占用、其他用户已分配端口，也未检查上限 | 统一分配器，保留有效端口；冲突时显示受影响用户并重新选择 |
| P1 | 删除协议：`delete_sb_protocol`、`delete_protocol` | Sing-box 缺少删除前统一确认；非法编号可能进入算术；删除或重启失败仍可能保存变量、报成功 | 显示受影响协议和用户；确认后事务删除，验证失败恢复 |
| P2 | 用户身份：`user_db_op`、`manage_users` | 中文等字符静默清洗成 `user` 或短名；显示名、内部名、email 不完全一致；菜单中英文混用 | 区分显示名与内部 ID；保存前显示规范化结果；统一语言与取消约定 |
| P2 | 流量与限额：`sb_collect_user_traffic`、生成的 `sb_collect.sh` | 手工采集函数的管道与 heredoc 争用 stdin；后台另有独立实现；端口文本匹配较宽 | 合并实现、精确匹配端口，测试重复采集、重启后增量和方向 |
| P2 | IPv6：`get_ip`、生成的 `sub_gen.sh`、iptables 路径 | 公网 IP 获取主要识别 IPv4；分享函数能处理 IPv6，但地址发现、跳跃和计数未全面覆盖 | 增加可编辑公网主机名/IP；分别检测 IPv4/IPv6 可达性和规则 |
| P2 | 自定义及聚合订阅：`add_custom_link`、`agg_menu` | 主要校验链接前缀；客户端不支持的节点缺少逐项原因；来源错误多在后台隐藏 | 显示解析预览、有效/无效原因和来源最近状态 |
| P2 | 中继/WARP：`relay_apply`、`warp_apply_routing` | 已有备份及部分校验，但与协议、用户后台任务使用不同写入路径和恢复边界 | 统一写入锁、候选文件和跨内核事务；显示分流优先级与生效状态 |
| P2 | 重装、卸载与维护：`do_install`、卸载分支、`legacy_*` | 缺少用户可操作的完整备份/恢复；旧不可达菜单与现有流程并存 | 增加配置包导入/导出、凭据保留选项；清理未调用菜单和重复逻辑 |

建议后续顺序：安装/升级健康检查和恢复 → 旧菜单校验与实际配置同步 → 删除事务和用户端口分配 → 订阅生成/端口检查 → 跳跃运行状态展示与统计统一。优先减少“面板显示成功但节点不可用”的情况。
