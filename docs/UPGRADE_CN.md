# 已部署 VPS 的更新方法

本次更新包含 VLESS-Argo / VMess-Argo 独立管理，以及配置、服务、统计和 WARP 的维护重构。正常运行中的 VPS **无需重装，也无需为此次更新替换代理内核**。

## 更新步骤

1. 在当前面板输入 `0`，退出到 SSH 命令行。
2. 使用原来的管理命令重新进入：

   ```bash
   ag
   ```

   `ag` 会下载并检查 GitHub `main` 的最新脚本，然后打开新版面板。

3. 如果 `ag` 不可用，可以直接运行：

   ```bash
   bash <(curl -fsSL "https://raw.githubusercontent.com/m2dumpling/ArgoV/main/argov.sh?r=$RANDOM$RANDOM")
   ```

   检测到已有 `/etc/xray/config.json` 后进入管理面板，不进入首次安装流程。

4. 进入新版后，等后台下一轮刷新，再在客户端手动更新订阅。正常情况下订阅生成器约每 10 秒被重新调用；具体刷新时间也取决于现有用户数量和网络请求。

首次升级建议按上述步骤从 SSH 命令行启动，避免仍在运行的旧面板继续执行旧逻辑。新版菜单 `8` 已在交接新版后退出旧面板，不再用旧函数重新生成后台文件。

## 更新时实际发生的操作

- 加载已有配置，并从实际入站识别 Argo 协议、端口和 WS 路径。
- 原子更新已存在的 `sub_gen.sh` 和 `sb_collect.sh`，先检查语法，内容相同时不改写；失败时保留该文件的旧版本。
- 运行中的订阅与统计服务下一轮调用新的辅助脚本，无需因此重启 Xray、Sing-box 或 Cloudflare 隧道。
- 保留节点端口、UUID、订阅 Token、用户及流量数据、证书和核心二进制；不会因为更新脚本而增加或删除协议。
- 不存在的辅助脚本不会仅因进入面板而新建，也不会额外安装或启动没有配置的核心。

## 删除 VMess-Argo 的例子

新版入口：

```text
ag → a → d2 → 确认
```

确认后刷新客户端订阅。该操作移除 VMess-Argo 的入站及对应转发规则，保留 VLESS-Argo 和其他协议；以后选择保留数据重装也不会恢复已删除的 VMess-Argo。

VLESS-Argo 对应 `d1`。添加入口是 `a4` / `a5`，编辑入口是 `e1` / `e2`，查看链接是 `v1` / `v2`。两种 Argo 协议仍共用隧道域名、CDN 和用户凭据。

实际增删改节点时会重启 Xray，同一核心的连接可能短暂断开。只删除其中一种 Argo 协议时不重启共享隧道；删除最后一种时停止隧道，重新添加时再启用。

## 菜单含义

| 菜单 | 用途 |
| --- | --- |
| `6` | 重启系统服务，包含 Xray，并非只重启 Argo |
| `7` | 保留数据重新安装；本次更新不需要使用 |
| `8` | 获取并进入最新管理脚本 |
| `x` | 独立更新 Xray 内核 |

若出现辅助脚本更新失败提示，旧文件仍保留；检查 `/etc/xray` 的磁盘空间及写入权限后重试进入面板。周期性全节点失效的现场诊断与这次脚本升级是不同问题，重装恢复本身不能证明已经消除故障根因。
