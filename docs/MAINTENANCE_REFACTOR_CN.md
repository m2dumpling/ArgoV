# 脚本维护结构审视与兼容重构

日期：2026-11-06。以本地 Argo 独立协议管理版本为起点审视完整 `argov.sh`；本轮不改变安装的单文件交付方式。

## 已完成的整理

| 模块 | 原设计问题 | 本轮处理 |
| --- | --- | --- |
| 配置持久化 | 安全加载白名单与保存字段分别维护，新增字段容易只改一处 | `ARGOV_CONF_KEYS` 统一维护原有 93 个字段；加载与保存共用清单，保留字段顺序、Shell 转义、默认值、文件权限及写入锁 |
| 服务平台适配 | 已有 systemd/OpenRC 兼容层，调用方仍同时执行两套命令，Alpine 可能重复重启 | 生命周期统一走兼容层，共用服务集合和状态展示；OpenRC 批量操作保留任一服务失败的信息 |
| 服务状态 | Alpine 将 `crashed` 或匹配到的其他进程当成服务运行 | 状态判断使用服务管理器返回值；面板菜单 6 改称“重启系统服务”，原有动作范围保留 |
| 启动入口 | 加载函数定义会立即执行迁移、安装与主菜单；测试依赖截断固定的文件尾部 | `argov_main` 管理启动编排；`source` 可加载函数，直接执行、`bash <(curl …)` 和管道输入仍可正常启动；取消安装后返回失败 |
| 旧菜单 | 两套无人调用的 `legacy_*_unused` 菜单与有效实现共存 | 确认没有调用后删除两套旧菜单；旧配置及 ArgoX 数据迁移流程保留 |
| Sing-box 统计 | 前台与守护进程各实现一次；前台管道与 heredoc 争抢 stdin；后台使用固定临时 Python 文件 | `emit_sb_collect_script` 生成唯一的采集实现，前台与后台共用；程序与数据分别使用 stdin 和 fd 3，移除固定临时文件 |
| 统计采样 | 每个端口重复读取 iptables，端口前缀可误匹配，两个采集者可能先采样后排队回写 | 每轮最多读取 INPUT/OUTPUT 各一次；精确匹配端口字段；锁覆盖采样及回写，用户文件以唯一临时文件原子替换 |
| WARP | 普通应用与模式切换各自改写 JSON、重启、回滚，区别隐含在两段重复实现里 | 共用候选配置写入及重启/回滚；显式区分普通应用保留 IPv6 规则与模式切换替换规则；校验通过后才替换配置 |
| 内核校验 | 候选文件扩展名随机，Xray 自动格式识别可能拒绝有效 JSON | 共用校验显式指定 `-format json`，并在原目录将候选文件统一为 `.json` 后缀；覆盖 Argo、HY2 与 WARP 的候选配置 |
| 菜单反馈 | 节点操作报错后立即重绘菜单，回滚原因难以看到 | 交互终端中操作失败或取消后等待回车，保留输出；管道输入不增加等待步骤 |
| 存量部署升级 | 主脚本更新后，已生成的订阅与统计脚本仍可能是旧实现；旧面板退出新版后可能再次写入旧脚本 | 进入面板时原子刷新已存在的生成器与采集器，语法预检、内容相同不改写；新版菜单 8 交接后退出旧流程 |

## 兼容边界

- 部署仍使用一个 `argov.sh`，安装产物不依赖仓库目录、外部分拆模块或新增 Python 包。
- 配置字段、订阅地址、用户 UUID/Token、协议端口、WS 路径、证书及已有流量累计字段继续沿用；上一轮的 Argo 独立管理入口继续保留。
- Sing-box 历史字段 `sb_prev_in` 存 OUTPUT 累计、`sb_prev_out` 存 INPUT 累计，本轮保留这一存储约定，按用户上传/下载方向计算增量。采样计数器归零后沿用原有基线重建方式。
- WARP 普通应用只替换 `warp-out`，保留已有 `v6-direct`；模式切换会替换两种出站。智能分流的域名集合、规则优先级及其他路由保持原语义。
- 服务“运行中”仍表示服务管理器状态；它不能代替客户端到公网的实际连通性检查。

### Xray 26.10.31 删除回滚的后续修复

用户现场日志显示，删除 VMess-Argo 时随机后缀的候选文件被拒绝，随后快照回滚。之前使用 26.3.27 验证通过的 `-format json` 不能覆盖新版的后缀检查；[26.10.31 外部加载器源码](https://github.com/XTLS/Xray-core/blob/v26.10.31/main/confloader/external/external.go#L48)也明确检查普通文件的扩展名。

共用提交函数现会在原目录将候选文件改名为 `.json` 后再校验，成功后原子替换配置，校验失败则删除候选文件并保留原配置。原目录重命名不依赖 GNU `mktemp --suffix`，也不会改变配置相对路径的解析位置。交互菜单失败时等待回车，避免重绘清掉错误信息。

后续回归使用官方 Xray 26.10.31 二进制（核对发布方 SHA256），完整 106 项检查通过且无跳过项，包含真实增删改、三种 Argo 组合的 WebSocket/SOCKS/HTTP 互通、三种 WARP 模式校验及拒绝回滚。新增检查覆盖随机候选后缀、已有 `.json` 后缀和校验失败后的文件清理；终端模拟检查确认错误显示后等待回车、原 VMess 入站仍保留。另在 26.3.27 下复核 Argo 与维护重构共 38 项检查。

26.10.31 的回环互通测试需在临时服务器配置中仅放行本次 HTTP 测试目标的地址与端口，以适应[新版 Freedom 的默认私网目标限制](https://github.com/XTLS/Xray-core/blob/v26.10.31/proxy/freedom/freedom.go#L151)。此设置只存在于隔离测试配置，不写入部署脚本生成的节点配置。

## 仍需谨慎处理的结构

这些模块已审视，但需要进一步设计迁移与实机验证：

1. `argov.conf` 与两种核心 JSON 同时保存部分协议状态；Argo 已从实际入站回填，其余协议尚未全面统一数据来源。
2. Xray 的普通用户同步与配额守护程序仍各有一段 Python 配置同步逻辑；后台多个写入者的跨文件事务边界尚未统一。
3. 首次安装与保留数据重装的全流程尚未使用统一快照事务；生命周期菜单仍有 best-effort 操作。Reality/SS 增删改和普通协议删除已在后续 [Xray 多版本复核](XRAY_VERSION_MATRIX_CN.md)中接入候选配置及回滚，安装也已增加启动前预检。
4. 首次安装端口分配、Sing-box 用户端口分配、订阅 HTTPS 端口选择仍有独立规则，需要单独验证历史部署的兼容行为。
5. HTTPS 订阅、聚合转换和多协议导出仍集中在较长的生成模板里；后续拆解应继续保留单文件安装与现有 URI 兼容契约。

本轮没有改写这些业务规则，也不能据此认定已经修复特定 VPS 周期性全节点失效的根因。
